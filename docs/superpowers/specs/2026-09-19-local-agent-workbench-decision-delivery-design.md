# Local Agent 工作台视觉重设计规格

## §0 当前状态、结论与确认边界

2026-09-20：此前“任务回执、决策与交付 UI”增量方案的**功能实现仍可作为行为基线，但视觉验收结论撤回**。旧方案把“参考 Steadbot”解释成在现有蓝灰三栏中增加回执、决策卡和文件卡，并明确要求保留原列宽和视觉系统；这不能满足用户要求的“能明显看出参考了 Steadbot”的前端设计目标。

本文原位替换旧规格，采用已经确认的方向：

> **复刻 Steadbot 的可见产品形态，保留 Local Agent 的真实业务语义。**

2026-09-20：用户已确认本规格与独立高保真对比稿，**设计 Gate PASS；前端重构、固定离线验证与最终代码 Gate 也已 PASS**。实现按[新实施计划](../plans/2026-09-20-local-agent-workbench-visual-redesign.md)从语义 DOM 和设计 Token 整体替换旧页面，没有继续在旧页面尾部追加 CSS；真实模型未调用，用户最终体验验收待进行。

视觉确认材料：[可交互对比稿](../mockups/2026-09-20-local-agent-workbench-comparison.html)与[固定截图](../mockups/2026-09-20-local-agent-workbench-comparison.png)。

本设计阶段完成条件（已满足）：

- 规格明确桌面、平板、手机的信息架构、视觉语言、组件、状态与验收口径。
- 对比稿能一眼看出旧版与目标版在页面骨架、信息密度和注意力顺序上的差异。
- 新设计不伪造 Todo、Cron、多 Agent 或当前后端不存在的持久状态。
- 用户已明确确认对比稿；前端重构另以实现、测试、截图和最终代码 Gate 证据判定为完成。

## 1. 设计来源与纠偏决定

### 1.1 参考来源

本设计以 Steadbot 主分支的以下一手材料为参考：

- [设计理念](https://github.com/arelchan/steadbot/blob/main/docs/design.md)：通信软件外壳、异步委托、事项凭证、界面不解释自己。
- [主界面截图](https://github.com/arelchan/steadbot/blob/main/.github/assets/hero.png)：窄联系人栏、开放式对话、紧凑工作栏和底部输入框。
- [视觉样式](https://github.com/arelchan/steadbot/blob/main/bot-crew/src/styles.css)：暖纸色、赤陶色强调、发丝分隔、低阴影和克制圆角。
- [首页与日程设计](https://github.com/arelchan/steadbot/blob/main/bot-crew/docs/home-calendar-design.md)：页面优先回答“什么在等我、下一步是什么、什么时候发生”。

参考的是视觉层级和交互形态，不复制 Steadbot 当前才有的产品能力。

### 1.2 三种路线与最终选择

| 路线 | 内容 | 结论 |
|---|---|---|
| A · 继续增量润色 | 保留旧 DOM 和三栏技术面板，只换颜色与间距 | 拒绝。无法形成可见的设计变化，也是上一版失败的原因。 |
| B · 形态复刻、语义保留 | 重建页面骨架与样式，使用 Steadbot 的通信软件形态；Session、Run、审批和证据仍来自 Local Agent | **采用。** 用户能感知设计变化，同时不制造后端不存在的事实。 |
| C · 产品模型整体复制 | 引入永久 Bot 对话、Todo、日历、Cron、多 Agent 群聊 | 拒绝。需要新的领域模型和后端协议，超出本阶段。 |

### 1.3 本次纠偏不是“换皮”

必须同时改变：

1. 页面骨架：从“后台仪表盘三栏”改为“联系人／会话 + 对话主舞台 + 工作状态栏”。
2. 信息优先级：先显示对话、待确认和交付；模型次数、Trace、能力配置退到按需详情。
3. 视觉语言：从雾蓝技术后台改为暖纸色通信软件。
4. 内容形态：普通回答不装进卡片，只有决策和交付使用强卡片。
5. 输入方式：从整块底部表单改为悬浮式 Composer，设置渐进披露。

只修改色值、阴影或圆角不能通过验收。

## 2. 产品目标与非目标

### 2.1 目标

工作台打开后，用户应在五秒内回答：

1. 我正在和哪个助手、哪个 Session 对话？
2. 现在有没有事情在等我决定？
3. 这一轮最终回答和文件在哪里？

同时保留工程核查能力：用户仍能找到引用、审批历史、Artifact 校验值和 Trace，但这些信息不能默认占据主视野。

### 2.2 非目标

- 不新增 Todo、Cron、日历、并行 Run、多 Agent 群聊或共享桌面。
- 不移除 Session，也不把一个助手强制变成唯一永久对话。
- 不改变 `liveRunId`、`inspectedRunId`、审批、取消、继续运行或 Artifact 下载协议。
- 不改变写入授权和“不覆盖已有文件”的安全边界。
- 不增加外部字体、UI 框架、遥测或网络资源。
- 不在视觉稿阶段修改产品 HTML、CSS、JavaScript 或后端。

## 3. 核心设计原则

### 3.1 对话是主角

中栏必须拥有最大面积和最少视觉噪音。用户消息使用轻量暖灰气泡；Agent 回答直接排版在纸面上，不使用统一白卡包裹。

### 3.2 状态替用户守门

右栏不是通用 Inspector，而是紧凑的工作状态栏，按“等你确认 → 进行中 → 已完成”排列。每项都必须能回到真实 Run；没有数据时不展示虚构卡片。

### 3.3 强卡片只属于行动和交付

只有需要用户批准或拒绝的决策，以及已由持久 Artifact 证明的交付文件，使用完整卡片。引用、步骤、模型信息和能力配置使用文字行、折叠详情或独立 Sheet，不与决策争夺注意力。

### 3.4 技术证据渐进披露

默认界面说人话；“运行详情”中保留精确状态、调用次数、引用和 Trace。隐藏不等于删除，简化不等于猜测。

### 3.5 状态必须来自真源

界面只投影已有 Session、Run、Approval、Citation 和 Artifact。模型文字不能制造成功状态；颜色不能代替状态文字。

## 4. 桌面信息架构

### 4.1 页面骨架

桌面宽度 `>= 1200px` 时使用三段式应用壳，但它不再是三个等价技术面板：

```text
┌ Agent 轨 56 ┬ 当前 Agent 会话 176 ┬ 对话主舞台 min 640 ────────┬ 工作状态 288 ─┐
│ 产品入口     │ Agent 名 / 工作范围 │ Agent / Session / 连接状态 │ 等你确认      │
│ Agent A      │ 当前 Session        │                             │ 进行中        │
│ Agent B      │ 历史 Session        │ 用户消息                    │ 已完成        │
│ Agent C      │ 新建会话            │ Agent 回答                   │              │
│              │ 资料 / 设置         │ 决策卡 / 文件卡              │ 运行详情入口  │
│ 管理 Agent   │                     │ 悬浮 Composer + 模型状态     │              │
└──────────────┴─────────────────────┴─────────────────────────────┴──────────────┘
```

- 左侧整体固定 `232px`：`56px` Agent 切换轨 + `176px` 当前 Agent 会话栏。它们是同一个导航区域，但职责分开。
- 中栏占剩余空间，正文阅读宽度 `680–760px`，对话周围保留明显留白。
- 右栏固定 `288px`，只显示当前 Session 的注意力队列和最近交付。
- 三段之间只使用 `1px` 发丝分隔，不使用整栏阴影和多重嵌套边框。

### 4.2 左栏：固定 Agent 轨 + 当前 Agent 会话

桌面端采用两级固定导航：

1. **Agent 切换轨（56px）**：持续显示全部已启用 Agent。每个 Agent 使用稳定的首字母／线性图标和可访问名称；当前 Agent 同时以描边、底色和 `aria-pressed` 表达，不能只换颜色。停用 Agent 留在管理页，不占日常切换轨。
2. **当前 Agent 会话栏（176px）**：顶部显示当前 Agent 名、策略／资料范围摘要和新建会话；下方只列出 `session.agent_id` 与当前 Agent 一致的 Session。

切换 Agent 时，会话栏必须整体切换到该 Agent 的会话集合；没有会话时显示简短空状态和“新建会话”。当前 Session 使用低对比暖色底，并显示真实的 `运行中／待确认` 状态。Session 标题旁可显示文件名或目录范围，让用户分清不同工作范围；这只是 `SessionScope` 的投影，不得暗示每个 Agent 拥有后端尚未支持的独立文件系统根目录。

资料、Skill、MCP 和工具配置属于当前 Agent，进入其设置 Sheet；资料也可从 Composer 附件动作进入。右侧工作状态栏不承担 Agent 配置。

平板和手机不强塞两级固定栏：平板保留 `56px` Agent 轨，会话列表从当前 Agent 旁弹出；手机在对话顶栏使用 `Agent 名 + 下拉箭头` 的锚定切换器，选择 Agent 后再显示其会话列表。两种形态使用同一选择状态，不维护第二份 Agent 数据。

### 4.3 中栏：连续对话

顶部栏高度 `56px`，只显示助手名、当前 Session、本机连接或执行状态，以及窄屏时的左右栏按钮。

- 用户消息右对齐，最大宽度为正文区的 `72%`，暖灰气泡，无深蓝大色块。
- Agent 回答左对齐并直接排版，不添加卡片底和阴影。
- Run 回执缩为一行元信息：状态文字、时间、引用数、文件数；不再单独形成浅蓝框。
- 历史失败紧邻对应 Run，使用图标、标题和恢复动作，不用整段红底。
- “查看本轮”改为文字按钮 `运行详情`，打开按需 Sheet，不改变 `liveRunId`。

底部 Composer 在中栏内悬浮，最大宽度 `760px`，距底部 `20–24px`。默认显示输入区、附件／资料动作、发送按钮，以及类似 Codex Composer 的模型状态行：`状态点 + 模型名 + 当前状态 + 展开箭头`。

模型状态行的数据契约：

- 已选择持久 Session 时，模型名来自 `activeSession.agent_snapshot.model.name`，保证旧会话显示创建时冻结的模型，而不是套用 Agent 的最新配置。
- 临时任务或新建 Session 前，模型名来自当前 `selectedAgent.model.name`。
- Provider 可用性来自 `/api/config` 的 `ready/provider/error`；运行状态来自当前真实 Run，不从文案猜测。
- 映射为：空闲且 Provider 可用 → `就绪`；`queued` → `排队中`；`running` → `调用中`；`waiting_approval` → `等待确认`；Provider 配置错误 → `不可用`。
- 状态行点击后只打开只读模型详情（Provider、模型名、Agent 修订、会话快照说明）。当前 Session 的模型不可在 Composer 内切换；修改 Agent 模型只影响之后创建的新 Session。

不显示后端没有提供的上下文剩余量、价格、速率或“智能程度”。输出路径、目录模式及其他运行设置收进 `任务设置` popover/sheet；当必填项缺失时在输入区下方就地提示。Enter 发送、Shift+Enter 换行保持不变。

### 4.4 右栏：工作状态

右栏不是第二份技术正文，只回答“哪里需要我”和“刚刚交付了什么”。顺序固定：

1. **等你确认**：当前 `waiting_approval` Run；有且只有一个主行动入口。
2. **进行中**：当前 `queued/running` Run；显示任务标题和已发生的真实阶段。
3. **已完成**：当前 Session 最近的 `completed` Run 和持久 Artifact。
4. **运行详情**：打开详情 Sheet；不在栏内展开 Trace、能力配置或完整引用。

Local Agent 当前只允许一个在途 Run，因此右栏不伪装成多任务看板。分组可以为空；为空时只显示两三个字的静默空状态。

### 4.5 运行详情 Sheet

从右侧覆盖打开，桌面宽度 `420–480px`。内容顺序为执行概览、只读审批历史、Artifact、原文依据和默认折叠的 Trace。Sheet 关闭后回到原触发控件。查看历史 Run 只改变 `inspectedRunId`，不迁移 live 决策卡、不改变审批、取消或继续运行的目标。

## 5. 视觉系统

### 5.1 颜色 Token

| Token | 值 | 用途 |
|---|---:|---|
| `--canvas` | `#F1EDE5` | 应用外层、左栏与右栏基底 |
| `--paper` | `#FBFAF7` | 对话主舞台 |
| `--paper-raised` | `#FFFFFF` | 决策卡、文件卡、Sheet |
| `--ink` | `#26221D` | 主文字 |
| `--muted` | `#756F67` | 次级说明 |
| `--hairline` | `#DED7CC` | 分隔线 |
| `--accent` | `#9A4B28` | 主行动、当前焦点、等待确认 |
| `--accent-soft` | `#F2E3D8` | 轻选中、用户气泡、注意力底色 |
| `--success` | `#3F6B50` | 已完成 |
| `--danger` | `#9A3F38` | 失败与拒绝 |

状态不得只靠颜色表达，必须同时有图标或文字。

### 5.2 字体、空间与效果

- 使用系统字体栈：`-apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", sans-serif`，不发网络请求。
- 正文 `15px/1.7`；移动端输入和正文不小于 `16px`。
- 页面标题 `18px/1.3`，区段标题 `13–14px`，辅助信息最小 `12px`。
- 仅 Run ID、SHA-256、路径和 Trace 使用等宽字体。
- 去掉 `RUN INSPECTOR`、`CURRENT RUN` 等英文大写 Kicker，用户界面使用简短中文。
- 使用 `4/8px` 间距节奏；主区段间距 `24–32px`。
- 普通气泡圆角 `14px`，决策／文件卡 `16px`，Composer `20px`。
- 只有 Composer、Sheet、决策卡可使用一级柔和阴影；栏、普通消息和状态列表不用阴影。
- hover、focus、pressed 过渡 `150–220ms`；尊重 `prefers-reduced-motion`。

## 6. 核心组件规格

### 6.1 Run 元信息行

展示状态、时间、引用数、文件数和 `运行详情`。它是对话内容的注脚，不是卡片。`completed` 只有存在有效 `result.answer` 才能显示“已完成”。

### 6.2 决策卡

决策卡直接嵌入当前 Run：`需要你确认` 与倒计时、一句人话说明、目标路径／操作类型／大小／风险、默认折叠的完整预览、主按钮 `允许创建` 和次按钮 `拒绝`。

卡片使用暖白底和赤陶色左边标识，不使用黄色整块表单。操作仍严格绑定 `liveRunId + approval_id`；历史卡只读。

### 6.3 文件卡与预览

持久 Artifact ID 存在后才显示文件卡。卡片包含一致的线性文件图标、文件名、相对路径、大小、状态、预览和下载；SHA-256 放入“校验信息”折叠区。文件卡优先出现在产生它的回答下方；右栏只显示最近交付的紧凑入口。

桌面预览使用接近全画布的 Overlay，而不是小型技术弹窗：最大宽度 `1080px`、最大高度 `calc(100dvh - 64px)`。正文仍通过认证下载接口取得，严格 UTF-8 解码并用 `textContent` 写入 `<pre>`，不执行 Markdown、HTML、脚本、图片或链接。

### 6.4 轻量工作项

右栏工作项只含状态、任务标题、更新时间和必要动作。它是现有 Run 的投影，不创建第二套状态机。

## 7. 数据、状态与竞态

| 后端状态 | 用户文案 | 右栏分组 |
|---|---|---|
| `queued` | 已接收 | 进行中 |
| `running` | 正在处理 | 进行中 |
| `waiting_approval` | 等你确认 | 等你确认 |
| `completed` + 有效回答 | 已完成 | 已完成 |
| `unable` | 未完成 | 对应 Run 内展示 |
| `validation_failed` | 校验失败 | 对应 Run 内展示 |
| `timed_out` | 已超时 | 对应 Run 内展示 |
| `cancelled` | 已取消 | 对应 Run 内展示 |
| `interrupted` | 已中断 | 有恢复能力时显示“继续” |
| `failed` | 失败 | 对应 Run 内展示 |

`RunReceiptProjector`、`DecisionCardView`、`ArtifactCardView`、`ArtifactPreviewController` 和 `SessionAttentionProjector` 的行为继续作为重构约束，但不要求保留旧 DOM 或旧 CSS。新增两个纯视图投影：

- `AgentWorkspaceProjector(agents, sessions, selectedAgentId)`：按 `agent_id` 输出固定 Agent 轨、当前 Agent 的会话和真实 SessionScope 摘要。
- `ModelStatusProjector(config, selectedAgent, activeSession, liveRun)`：输出 `{provider, model, status, source}`，其中 `source` 明确是 `agent` 或 `session_snapshot`。

实施计划必须先建立新的语义 DOM，再把这些模块接回新挂载点。

- `liveRunId` 只决定轮询、审批、拒绝和取消。
- `inspectedRunId` 只决定详情 Sheet 查看哪一轮。
- 切换 Session／Agent 后，旧代次请求不得写入新视图。
- 文件已创建但回答随后失败时，文件卡保留，Run 状态仍如实显示失败。
- Session 列表接口没有证据时，不显示跨重启“未读／等你”。

## 8. 响应式规格

| 视口 | 结构 |
|---|---|
| `>= 1200px` | `56px` Agent 轨、`176px` 会话栏、对话和右栏常驻；详情为覆盖式 Sheet。 |
| `768–1199px` | `56px` Agent 轨常驻；会话列表为锚定浮层，右栏收进抽屉；对话优先。 |
| `< 768px` | 单栏对话；Agent／会话从顶栏下拉或抽屉切换，工作栏为独立抽屉；Composer 贴合安全区。 |

必验宽度：`375 × 812`、`768 × 1024`、`1024 × 768`、`1440 × 900`。

- 不出现页面级横向滚动。
- 输入框、发送和待确认主按钮始终可达。
- 触控目标至少 `44 × 44px`。
- 移动端先显示对话；技术详情不得挤占首屏。
- Composer 的模型名和状态在所有视口保持可见；空间不足时先隐藏 Provider 名，不隐藏状态文字。
- 最大系统字号下允许文本换行，不截断决策目标和文件名。

## 9. 可访问性、安全与隐私

- 使用语义化 `nav/main/aside/article/button/dialog`，标题层级连续。
- 图标来自同一线性图标体系；图标按钮必须有可访问名称。
- 交互控件有可见 `:focus-visible`，对比度达到 WCAG AA。
- 动态状态用 `aria-live="polite"`；错误使用 `role="alert"`，但历史状态不重复播报。
- 决策卡出现时，仅在用户没有输入时移动焦点；操作完成后焦点回到结果。
- 所有问题、回答、路径、审批、引用和文件正文继续通过 `textContent` 写入。
- 不扩宽 CSP，不新增网络资源，不绕过现有认证 Artifact 下载入口。

## 10. 实施边界

## 11. 高保真对比稿验收点

对比稿不是产品完成证据，只用于确认视觉方向。它必须清楚展示：

- Composer 悬浮于对话底部，而不是一整块设置表单。

用户确认的对象是页面骨架、视觉语言和注意力顺序，不是稿中的示例文字或虚构运行数据。

## 12. 前端最终验收标准

### 12.1 视觉与产品验收
