# Local Agent 会话工作台设计

## §0 当前状态与完成边界

2026-09-15：**视觉方向与信息架构已由用户确认，设计 Gate PASS，进入实施。** 用户选择三栏会话工作台和“雾蓝 × 琥珀”主题。Gate 对照现有前端、HTTP 接口、审批与会话状态契约完成；未发现 P0/P1/P2，改版后的浏览器行为与视觉效果留给实现验收证明。

本轮要验证的假设是：**不改 Runtime、会话、工具、Skill 或 MCP 协议，只重组现有网页，就能让用户像使用聊天产品一样选择助手、持续对话、处理工具审批并核对依据。**

完成条件：现有能力在一个桌面工作台中可发现、可操作；运行状态与审批不会被视觉包装掩盖；移动端可完成同样的核心流程；既有前端安全和状态契约保持通过。固定验收通过后即收口，不追加新的 Agent 能力。

本文件是前端设计，不代表代码已实现。实现进度后续由实施计划维护。

## 1. 来源与选择

参考 [Steadbot 当前主分支](https://github.com/arelchan/steadbot) 的会话页层级：左侧负责定位助手与会话，中间承载自然语言对话，右侧承载持续任务状态和结果检查。借用信息结构，不复制其品牌、头像、演示数据或陶土色主题。

前期比较了三种布局：

| 方案 | 特点 | 结论 |
|---|---|---|
| A 三栏会话工作台 | 助手/会话、对话、运行检查各有稳定位置 | **采用**。最贴合持续使用，也能容纳现有审批与证据 |
| B 两栏轻量聊天 | 更简洁，但工具、引用和能力管理容易挤进对话 | 不采用 |
| C Runtime 检查台 | 技术信息最完整，但日常提问成本高 | 不采用 |

视觉主题比较后选择 **A：雾蓝 × 琥珀**。视觉服务于状态区分和长时间阅读，不改变产品能力。

## 2. 产品主线与范围

页面仍服务于同一个闭环：用户提交问题 → 模型自主请求工具 → Runtime 校验并执行 → 结果回填下一轮 Context → 模型回答或合理结束 → 用户可核对引用、审批和执行记录。

本轮包含：

- 把现有长页面改成桌面三栏会话工作台。
- 让三个内置助手、持久会话、工具、Skills、MCP 和运行证据容易发现。
- 把问题输入改为底部 Composer，把次要配置折叠到“本轮设置”。
- 把运行中、待审批、失败、取消、完成和中断状态放到用户视线内。
- 接入后端已有的会话与 Run 游标，提供“加载更多”，避免页面永久只显示前 20 条。
- 补齐键盘焦点、触控尺寸、状态文本和移动端布局。

本轮不包含：

- 新的 Runtime、Provider、工具、Skill 机制或 MCP 协议能力。
- 自动子 Agent 协作、群聊、共享计算机、Cron、Memory、远程 MCP/OAuth、流式生成。
- 把 Steadbot 的机器人形象、品牌语言或业务示例复制进本项目。
- 为视觉效果引入前端框架、组件库、外部字体、埋点或网络资源。

## 3. 信息架构

桌面端占满 `100dvh`，页面本身不纵向滚动；左栏、中栏和右栏分别独立滚动。推荐宽度为 `272px / minmax(480px, 1fr) / 344px`。

### 3.1 左栏：助手与会话

左栏回答两个问题：“我正在和谁工作？”“我要继续哪段对话？”

从上到下包括：

1. Local Agent 品牌、连接状态和当前 Provider。
2. 当前助手卡片：名称、简短说明、启用状态和切换入口。
3. “新建会话”主按钮；展开后填写名称和固定资料范围。
4. 会话列表：活跃会话在前、归档会话在后；每项显示标题、范围类型、最近状态和更新时间。
5. 当前会话的改名、归档或恢复操作。
6. 底部“管理助手与能力”，打开原有 Agent、Skill、MCP 管理内容。

保留“临时任务”入口，但与持久会话明确区分。切换助手后只显示属于该助手的会话，不能让视觉列表绕过后端归属校验。

### 3.2 中栏：持续对话

中栏是主要工作区，从上到下包括：

1. 会话头：标题、固定资料范围、助手修订和归档状态。
2. 对话历史：按时间显示本会话 Run。每项至少展示用户问题、任务状态和时间；点击后展开该 Run 的完整回答。首次进入只展开最新一项，旧项按需读取，避免一次请求全部详情。
3. 当前运行卡：展示模型正在准备、调用哪个工具、等待确认、正在结束或已经停止。工具调用显示工具名称与用户可理解的动作，详细事件仍放在右栏。
4. 审批卡：保留完整文件内容预览、目标路径、字节数、来源、风险、模型意图和倒计时。批准与拒绝是当前页面唯一的高强调操作。
5. 回答卡：回答、复制按钮、失败说明和继续中断任务入口。
6. 底部 Composer：问题输入、提交、取消以及紧凑的本轮设置。

Composer 默认只展示文本框和发送按钮。其上方用可移除的设置标签展示当前任务类型、资料范围、指定 Skill、MCP Prompt 和可选输出文件。点击“本轮设置”后展开现有字段；这些字段仍使用当前值、校验和接口，不创建第二套表单状态。

“核对资料”和“聊这段记录”继续是不同任务类型。会话固定范围时，Composer 只展示范围摘要，不允许在本轮偷换文件或目录。

### 3.3 右栏：本轮工作

右栏回答：“这轮发生了什么，依据和产物在哪里？”包含四个可折叠区：

| 区域 | 内容 |
|---|---|
| 本轮 | 状态、模型、调用次数、来源范围、取消/中断信息和执行步骤 |
| 依据 | 原文引用、目录发现/读取/未读取范围；引用可逐条核对 |
| 产物 | 已创建文件、字节数、SHA-256 和创建状态 |
| 能力 | 当前助手绑定的内置工具、Skill、MCP 及可用/停用/错误状态 |

“执行记录”默认折叠。用户展开后看到现有事件名称和 Trace 路径，但不显示隐藏推理，也不将日志存在冒充任务成功。

### 3.4 能力管理

原有 `details#capability-management` 保留，视觉上改为右侧抽屉或右栏中的管理面板。它继续支持：

- 从模板创建助手并填写模型、说明、工具和预算。
- 从本地路径导入 Skill。
- 从本地配置导入和探测 stdio MCP。
- 绑定、启用、停用能力。

管理操作与日常对话分开，但不另建路由或后台页面。保存或停用后的成功/错误状态必须就地显示。

## 4. 当前可用模块的真实展示

界面只展示后端实际返回的能力；没有安装的 Skill/MCP 显示空状态，不生成示例成功项。

| 模块 | 当前可用行为 | 页面入口 |
|---|---|---|
| `file-qa` | 单个 `.md/.txt` 文件问答和原文引用 | 左栏助手 + 新建单文件会话 |
| `directory-qa` | 目录发现、跨文件读取和范围完整性 | 左栏助手 + 新建目录会话 |
| `project-brief` | 组合项目助手，可绑定 Skill/MCP | 左栏助手 |
| `read_file` | 读取授权范围内文本 | 模型自主调用，右栏显示结果 |
| `list_files` | 枚举授权工作区内支持文件 | 模型自主调用，右栏显示范围 |
| `write_file` | 模型选择文件名，可逐次新建多个文本文件；每份独立审批且不覆盖 | 中栏审批 + 右栏产物 |
| `session_history` | 查询同一持久会话的历史 | “聊这段记录” |
| 持久会话 | 新建、继续、改名、归档、恢复、跨重启保持 | 左栏会话 |
| Skill | 导入文本包、绑定、启停、本轮指定、按需读取正文 | 能力管理 + Composer 设置 |
| MCP | 本地 stdio Tool/Resource/Prompt 白名单、探测和调用 | 能力管理 + Composer 设置 |
| 运行控制与证据 | 取消、恢复中断、引用、范围、审批、产物回执和 Trace | 中栏 + 右栏 |

能力区同时说明边界：当前只有 DeepSeek Provider、同一时刻一个活跃 Run、本地 `.md/.txt`、本地 stdio MCP；Skill 脚本不执行。页面不使用“全部完成”“完整 MCP”“自动多 Agent”等超出证据的文案。

## 5. 关键交互

### 5.1 首次打开与开始任务

1. 页面先读取 `/api/config`、Agent、会话和能力状态。
2. 连接完成后选中默认助手及其最近会话；没有会话时展示可玩的三个助手和“新建会话”。
3. 用户创建会话，固定单文件或目录范围。
4. 中栏 Composer 获得焦点；用户提交问题后立即出现自己的消息与运行状态。
5. 提交按钮变为不可重复触发，取消保持可用。

临时任务沿用当前接口，不写入持久会话。页面需要显著标识“临时”，避免用户误以为刷新后仍能继续。

### 5.2 工具调用与审批

- 普通只读工具运行时，当前卡显示“正在读取文件”“正在列出目录”或实际 MCP/Skill 名称。
- 工具错误如实进入本轮卡；模型继续修正参数或结束时，页面不提前显示成功。
- `write_file` 每次请求都显示完整预览，用户决定后按钮立即锁定，避免重复提交。
- 历史审批只读；切回旧 Run 不重新出现可执行按钮。
- 允许后，只有收到实际 Artifact 回执才显示“已创建”；拒绝、超时或文件不存在不能使用成功样式。

### 5.3 切换、刷新与迟到响应

- 切换会话、助手或历史 Run 时递增现有视图代次；旧请求晚到不得覆盖当前内容。
- 刷新页面只恢复状态，不自动重复 POST、审批或工具调用。
- 当前运行尚未结束时，相关 Agent、会话和表单控件遵守既有禁用规则。
- 续页使用后端签名游标；“加载更多”只追加当前助手或当前会话的结果，切换后丢弃旧续页响应。

## 6. 视觉系统：雾蓝 × 琥珀

使用系统字体，保持离线与当前 CSP。建议 CSS Token：

```css
--canvas: #eef3f8;
--panel: #ffffff;
--panel-soft: #f5f8fc;
--ink: #172234;
--muted: #657389;
--line: #d7e1ec;
--brand: #3f6f99;
--brand-strong: #2f587d;
--accent: #d59642;
--accent-soft: #fff3df;
--success: #39745b;
--danger: #a54b4b;
--warning: #8a641f;
```

- 主背景用冷雾蓝，内容面板为白色；避免大面积渐变。
- 蓝色表示导航、焦点和信息；琥珀只用于审批、当前选择和少量重点。
- 成功、警告、失败同时使用文字和图标，不只依靠颜色。
- 面板圆角 12–16px、细边框、轻阴影；减少装饰，让信息密度来自层级而不是卡片堆叠。
- 过渡控制在 150–220ms，并尊重 `prefers-reduced-motion`。

## 7. 响应式与可访问性

| 宽度 | 布局 |
|---|---|
| `>= 1180px` | 完整三栏，右栏常驻 |
| `768–1179px` | 左栏窄化；右栏变为可打开抽屉 |
| `< 768px` | 单栏；会话列表、对话、运行详情按页面层级切换；Composer 固定在安全区上方 |

验收要求：

- 在 320、375、414、768、1024、1440px 不出现页面级横向滚动。
- 正文字号移动端不低于 16px；交互目标至少 44×44px。
- 正文和控件对比度达到 WCAG AA；键盘焦点清晰。
- 会话名使用可见 `<label>`；当前会话/Run 使用 `aria-current`。
- 运行容器使用 `aria-busy`；错误继续进入 `role="alert"`。
- 审批出现、运行结束和切换历史后，把焦点移动到相应标题或状态区，但不抢走正在输入的光标。
- `Esc` 关闭移动抽屉，焦点返回触发按钮；Tab 不落到隐藏区域。

## 8. 实现边界

主要修改以下现有文件：

- `local-agent/local_agent/static/index.html`：重组语义结构，增加必要的导航、抽屉和续页容器。
- `local-agent/local_agent/static/app.css`：重写布局、主题、状态、响应式和焦点样式。
- `local-agent/local_agent/static/app.js`：复用现有 API 与状态，渲染会话侧栏、Run 对话列表、右栏信息和游标续页。
- `local-agent/tests/browser_web.cjs`：更新界面行为断言并保留 XSS、迟到响应、审批不可重放等保护。

必须保留的协议：

- `meta[name=session-token]`、`X-Session-Token`、`X-Agent-ID` 和同源 POST 约束。
- 当前脚本使用的原有元素 ID、字段类型、`hidden/disabled/required/value/checked` 语义；如增加包装层，不另造一套独立状态。
- `#session-select` 的首个临时 option；允许视觉隐藏，但仍由同一状态驱动。
- `viewGeneration`、`sessionListGeneration`、`renderedRevision`、审批锁和取消状态保护。
- 所有模型内容、引用、路径、Skill/MCP 描述继续通过 `textContent` 写入，不使用不可信 `innerHTML`。
- `details#trace`、`details#capability-management`、`[data-management]`、`[data-question]` 和动态能力按钮的数据属性。

已知的“无法读取”与“本次未完成”浏览器断言漂移在本轮统一为一种真实状态文案。实现前先以当前产品语义确定期望，然后同步代码和测试，不通过放宽断言掩盖问题。

## 9. 验收与停止条件

### 9.1 必过路径

1. 打开页面，三个内置助手与其真实能力正确显示。
2. 新建单文件会话，提问后回答、引用和运行状态出现在正确区域。
3. 新建目录会话，发现/读取范围和跨文件引用可核对。
4. 切换历史 Run、会话和助手，不串答案、状态、审批或能力。
5. 发起多个 `write_file`，每份独立预览；批准后显示真实 Artifact，拒绝后无虚假文件。
6. 已安装 Skill/MCP 时显示绑定与实际调用；未安装时显示真实空状态。
7. 刷新运行中、等待审批、已完成和中断页面，状态恢复且不重复提交。
8. 会话和 Run 超过一页时可以加载更多，且游标不能跨范围复用。
9. 桌面、平板和手机尺寸可完成同一条核心路径。

### 9.2 验证层级

- 静态检查：HTML/JS 元素契约、`node --check`、CSS/HTML 基本校验。
- 浏览器回归：沿用本地 Mock Server 验证交互、XSS、审批、迟到响应、刷新和续页。
- 视觉检查：1440px 桌面、1024px 窄桌面、390px 手机截图；检查溢出、焦点和空/错/忙状态。
- 产品冒烟：使用现有本地服务完成一条单文件真实任务。若后端和 Prompt 未改，既有真实 DeepSeek 语义验收证据继续有效，不重新跑整套模型评测。

代码、浏览器回归和上述截图检查通过后，本轮 UI 交付收口。视觉微调、新模块或更复杂会话行为只有在固定路径失败时才继续，不以“更像参考项目”为由无限扩展。

## 10. 交付后的用户入口
