## 1. 目标

基于项目目录中的一份设计文档和两份会议逐字记录，制作一份面向 Agent 初学者的中文教学手册。手册需要让读者在 60–90 分钟内建立完整的基础认知，并可通过深挖章节将总学习时间扩展到 2–3 小时。

成品必须同时满足三个目标：

1. 快速理解 Agent、Agent Loop、Runtime、Context、Tool、Session、Memory 等核心概念。
2. 将所有概念映射回当前 Local Agent Runtime 项目，明确下一步做什么和暂时不做什么。
3. 对三份源材料建立完整证据索引，避免遗漏会议中的问题、示例、阶段建议和项目决定。

## 3. 信息保真原则

### 3.1 内容分类

每段有意义的源信息必须归入以下类别之一：

- 事实：材料明确描述的对象、流程或现状。
- 工程师观点：会议中提出的解释、经验和建议。
- 用户问题或偏好：会议中用户的疑问、理解和选择，例如不偏好 CLI。
- 已确认决定：已经明确同意的项目方向或下一步。
- 示例：用于解释概念的天气、文件、代码、工作总结、金价定时任务等例子。
- 未来设想：尚未进入首期范围的优化或扩展。
- 转写疑点：自动转写中可能存在误识别、同音词或术语错误的内容。
- 非实质内容：寒暄、口吃、无信息重复和会议操作噪声。

### 3.2 保留与改写边界

- 三份原文件不修改。
- 教学正文允许调整顺序和使用通俗语言，但不得改变原意。
- 寒暄、口吃和无意义重复不进入教学主线，但要在覆盖账本中标为非实质内容。
- 会议中的具体例子应保留其教学作用，不能只保留抽象结论。
- 同一主题在设计文档和会议中存在不同口径时并列展示，不擅自消除差异。
- 供应商、模型价格和行业现状等可能随时间变化的内容，只作为会议发生时的意见记录，不转写成当前事实。
- 由教学需要新增的比喻、流程图、伪代码、自检题和解释，统一标记为“教学解释”，不得伪装成原文结论。

### 3.3 来源标记

HTML 使用四类来源标签：

- `设计文档`
- `会议 01`
- `会议 02`
- `教学解释`

关键结论同时提供源文件、行号或会议时间戳。附录提供完整的章节覆盖矩阵和时间段覆盖矩阵。

## 4. 读者与学习成果

目标读者是尚未建立 Agent 工程体系认知、但即将参与当前项目开发的人。正文不假设读者已经了解 API、Context、Function Calling、Runtime、MCP 或 RAG。

完成 60–90 分钟主线后，读者应能独立说明：

1. 大模型、Agent、Agent Loop 和 Runtime 的区别。
2. Context 为什么能让无状态 API 表现出短期连续性。
3. Tool Calling 中模型、Runtime 和工具分别负责什么。
4. 工具结果为什么必须写回 Message List。
5. Agent 如何在继续调用工具与结束任务之间做判断。
6. Session、Context 和 Memory 的区别。
7. MCP、Skill、RAG/知识库和 Cron 为什么不属于第一个最小闭环。
8. 当前项目第一个应验证的最小单位是什么。
9. 首期不应提前投入哪些功能。
10. 如何依据 Trace、测试和阶段验收判断开发是否跑偏。

## 5. 教学结构

采用“分层混合式”结构：概念顺序服务于学习，同时通过来源标签和附录保持对会议顺序的可追溯性。

### 5.1 60–90 分钟主线

1. **使用说明与学习地图**：两种阅读路径、来源标签和证据规则。
2. **这个项目究竟要做什么**：求职作品定位、本地工作空间助手场景、Runtime 与聊天界面的区别。
3. **从大模型到 Agent**：生成模型的输入输出本质，以及数据不实时、没有状态、不能实际行动三个局限。
4. **Context**：System Prompt、User、Assistant、Message List、Tool List 和多轮状态。
5. **Tool**：工具的输入输出、描述、Schema、Function Calling 和 `read_file` 示例。
6. **Agent Loop**：直接回答或调用工具、执行、结果回填、再次判断与停止。
7. **Runtime / Harness**：Provider、Agent Core、Tool Runtime、Session、State、Memory、Security、Event、Observability 的关系。
8. **第一步到底做什么**：API 连通性检查与单 `read_file` 工具闭环的区别。
9. **开发防跑偏检查表**：范围、阶段、验证和与工程师对齐的检查点。

### 5.2 深挖章节

10. **Session、Context 与 Memory**：会话隔离、持久化、上下文窗口和记忆分层。
11. **上下文压缩**：阈值、结构化摘要、任务状态、结果和经验保留策略。
12. **长期记忆与知识库**：`memory.md`、用户偏好、客观事实、持续写入、注入、搜索和存储—加工—检索。
13. **Tool Runtime 与权限**：注册、发现、校验、错误、截断、取消以及读写删除权限边界。
14. **完成条件、验证与评测基准**：结束前强制检查、代码运行、文件复读、页面渲染和错误基准风险。
15. **Provider 与模型能力**：API 适配、Tool Calling、流式输出、Usage、成本、错误和模型切换。
16. **MCP、Skill、RAG/知识库和 Cron**：外围扩展如何回到统一 Context、Tool Registry 或 AgentRun。
17. **产品形态与企业交付**：内核与界面解耦，业务场景、可信数据和工作流程决定应用形态。
18. **完整工程路线图**：Phase 0–7、M1–M5、推荐目录、依赖方向、交付物、完成标准和测试重点。
19. **实际协作与学习方式**：约三周的原始估计、模块前后及时沟通、GitHub 同步、使用编码 Agent 开发和暂不先投入大量课程。

### 5.3 附录

- Agent 核心术语表及边界。
- 会议转写纠错和不确定词表。
- 三份材料中的例子和类比索引。
- 明确决定、建议、示例和尚未决定事项的分类表。

- 会议 01 按时间段覆盖矩阵。

## 6. 统一术语

教学手册采用以下规范用语，并保留会议中的原始说法作为旁注：

| 规范术语 | 教学定义 |
| --- | --- |
| Model | 接收输入并生成输出的模型本体，本身不负责真实工具执行和长期状态保存。 |
| Provider | 把不同模型 API 转换为统一请求、响应、流式事件、错误和能力声明的适配层。 |
| Agent | 一组模型、提示词、工具和策略配置所描述的执行主体。 |
| AgentRun | 一次从任务开始到完成、失败、取消或暂停的具体运行。 |
| Agent Loop | 模型判断、行动、观察结果并再次判断的循环。 |
| Runtime | 让一次 AgentRun 能真实运行所需的核心工程机制。 |
| Harness | 会议中用于描述模型外部工程框架或脚手架的词；本项目统一以 Local Agent Runtime 作为正式项目名称。 |
| Context | 一轮模型调用可见的 System Prompt、消息、工具、记忆和运行状态集合。 |
| Session | 一段连续交互及其消息、运行、工具调用、产物和摘要的容器。 |
| Memory | 被保存、压缩、检索并重新放入 Context 的信息。 |
| Tool | Agent 可以请求执行的一项原子操作。 |
| ToolCall | 模型对某个工具及其参数的一次调用请求与结果记录。 |
| Tool Runtime | 负责工具注册、校验、权限、执行、取消、错误和日志的系统。 |
| Skill | 完成某类任务的方法、约束和能力依赖包，不等同于原子工具。 |
| MCP | 将外部 Server 的 Tool、Resource 或 Prompt 适配进内部系统的协议与连接方式。 |
| Trigger | 创建 AgentRun 的触发来源，例如 CLI、Cron 或未来的 Webhook。 |
| Artifact | Agent 生成的文件、报告或其他持久化产物。 |
| Event / Trace | 描述运行状态变化和完整执行链路的结构化记录。 |

自动转写中的 `look`、`refile`、`redfile`、`tell list`、`tour list`、`方心靠`、`chrome`、`reg` 等词不能静默替换。成品在纠错附录中列出原词、可能术语、上下文证据和置信度。

## 7. HTML 视觉与交互设计

### 7.1 交付约束

- 单个自包含 HTML 文件，可离线直接打开。
- 不依赖外部字体、图片、CDN、框架或网络请求。
- HTML、CSS 和少量 JavaScript 全部内联。
- 即使 JavaScript 被禁用，正文、目录锚点和展开内容仍可阅读；搜索、进度和 Scroll Spy 作为渐进增强。

### 7.2 视觉风格

定位为“极简产品工作手册”，而非博客、营销页或炫技网页：

- 纸张感浅灰背景、深灰正文、单一蓝色强调色。
- 使用系统无衬线字体栈，避免离线字体依赖。
- 正文行宽保持约 65–75 个字符，行高 1.6–1.75。
- 采用统一的 4/8 像素间距体系和克制的边框、圆角、阴影。
- 不使用渐变、装饰性动效、Emoji 导航图标或大量卡片堆叠。
- 来源、警告、决定和教学解释不仅用颜色，还使用文本标签区分。

### 7.3 桌面导航

- 左侧固定浮动目录。
- 目录展示主线、深挖和附录三级分组。
- 当前章节根据滚动位置高亮。
- 顶部提供全文搜索。
- 底部显示阅读进度和返回顶部入口。
- 固定侧栏必须为正文预留空间，不能覆盖首段或正文。

### 7.4 移动端导航

- 侧栏收为可开合目录抽屉。
- 打开和关闭均可通过键盘及明确按钮完成。
- 正文保持单列，不产生整页横向滚动。
- 宽表格在自身容器内横向滚动。
- 所有触控目标至少 44×44 像素。

### 7.5 内容组件

每章按需要使用以下组件：

- 本章问题与阅读时间。
- 一句话结论。
- 通俗解释与准确术语。
- HTML/CSS 绘制的流程图或关系图。
- 伪代码块。
- 当前项目对应关系。
- 常见误区。
- 开发检查点。
- 3–5 个自检问题。
- 原文依据和来源标签。
- 可折叠深挖内容。

### 7.6 可访问性与动效

- 提供“跳到正文”链接。
- 使用连续的 `h1`–`h4` 标题层级。
- 所有交互元素可通过键盘访问，并具有明显焦点状态。
- 正文和界面文字达到 WCAG AA 对比度。
- 动效只用于导航、展开和状态反馈，持续 150–300ms。
- 尊重 `prefers-reduced-motion`，关闭非必要平滑滚动和过渡。

### 7.7 打印

打印样式隐藏侧栏、搜索框、阅读进度和浮动按钮，展开需要打印的教学内容，保留章节结构与来源标记，避免正文和代码块被不合理截断。

## 8. 页面数据流与错误处理

1. 页面加载后扫描章节标题和目录链接，初始化 Scroll Spy 和阅读进度。
2. 搜索仅在当前 HTML 的标题、正文、术语和来源标记中执行，不联网。
3. 搜索为空时恢复完整目录和正文状态。
4. 搜索无结果时显示清晰提示，并提供清除搜索的操作。
5. 锚点不存在时不拦截浏览器默认行为，避免 JavaScript 造成死链。
6. `IntersectionObserver` 不可用时退化为普通锚点导航，不影响阅读。
7. 展开状态只影响显示，不移除内容，也不影响打印和证据覆盖。

## 9. 验收标准

### 9.1 内容验收

- 设计文档 10 个一级主题及所有模块、阶段、里程碑、优先级和测试策略都有明确去向。
- 会议 01 与会议 02 的每个有意义时间段都有明确去向。
- 每段源信息都被标记为正文、深挖、附录或非实质内容。
- 所有教学补充明确标记，不与原文结论混淆。
- 不确定转写均进入纠错表，不静默修正。
- 不同口径并列呈现，并解释它们所在的阶段或语境。
- 交付前重新计算三份源文件校验值并复核覆盖矩阵。

### 9.2 教学验收

- 主线能在 60–90 分钟内读完。
- 深挖后总学习时间约 2–3 小时。
- 每个主线章节包含自检题和开发检查点。
- 读者能够回答第 4 节列出的十个核心问题。
- 第一个最小验证单元、完整 M1 和后续扩展之间的边界清晰。

### 9.3 HTML 验收

- 单文件离线打开，无外部网络依赖。
- 所有目录链接、正文锚点、来源回链和返回顶部功能有效。
- 全文搜索、当前章节高亮、阅读进度和折叠内容正常。
- 浏览器控制台无 JavaScript 错误。
- 在 375、768、1024、1440 像素宽度下完成布局检查。
- 固定导航不遮挡正文，移动端没有整页横向滚动。
- 键盘可以操作目录、搜索、折叠和返回顶部。
- `prefers-reduced-motion` 生效。
- 打印预览隐藏交互界面并保留完整正文和来源标签。
- 使用浏览器实际打开、交互并截图检查，不能只检查源代码。

## 11. 已确认决定

1. 三份源文件保持只读。
2. 最终只交付一份整合 HTML 教学手册。
3. 教学深度为概念、流程图、伪代码和阶段开发检查点，不绑定具体技术栈。
4. 采用 60–90 分钟主线与 2–3 小时完整学习的分层结构。
5. 采用分层混合式内容组织，而非完全按会议时间或完全按模块重排。
6. 使用极简产品工作手册风格和当前页面浮动式侧导航。
7. 内容必须严格参照设计文档和两份会议记录，不遗漏实质信息，不做大幅语义改写。
8. 交付前同时执行内容覆盖、教学效果和 HTML 交互验收。
